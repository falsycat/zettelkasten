# agent: suggest-bridge-notes

ノート間の依存関係グラフを解析し、孤立したクラスタを橋渡しする新規ノートを提案する。
ノートは**作成しない**。提案のみ行う。

## ステップ

### 1. データ収集

```bash
# クラスタ一覧（cluster_num\tnode_id\ttitle）
python3 .claude/skills/zettelkasten/scripts/list-clusters.py
```

これ一本でエッジ取得・Union-Find・タイトル付与まで完結する。同じ `cluster_num` のノードが同一クラスタ。

### 2. クラスタ分析

スクリプト出力をもとに以下を整理する：
- 各クラスタのメンバー ID とタイトル
- 各クラスタの主題・テーマ（タイトルから推定）
- クラスタのサイズ（ノード数）

### 3. クラスタ間の関連性評価

クラスタのペアごとに「意味的に橋渡し可能か」を評価する：
- テーマ同士に概念的なつながりがあるか
- 既存ノートの本文をいくつか参照して、橋渡しとなりうる概念が潜在していないかを確認

```bash
# 特定ノートの内容確認
cat cells/<ID>.md
```

無関係なクラスタペア（たとえば日記と技術メモ）は提案対象から外す。

### 4. ブリッジノートの提案

橋渡しが意味的に成立するクラスタペアそれぞれについて、以下の形式で提案する：

---

#### 提案 N: `<仮タイトル>`

**つなぐクラスタ**
- クラスタ A: `<テーマ>` （例: 2026060601〜2026060604、zettelkasten 方法論）
- クラスタ B: `<テーマ>` （例: 2026061301〜2026061316、行政法原則）

**提案する内容**
1文〜3文で、このノートが扱う具体的なアイデア・論点を説明する。

**クラスタ A 側の接続先**
- `[[<ID>|<タイトル>]]` — 接続理由

**クラスタ B 側の接続先**
- `[[<ID>|<タイトル>]]` — 接続理由

**リンク方向**
`note-format.md` のルール（具体→抽象）に従い、どちらのノートからリンクを張るかを明記する。

---

### 5. 出力まとめ

最後に以下をまとめて出力する：

- クラスタ一覧（ID 範囲・テーマ・サイズ）
- 提案したブリッジノートの一覧（提案番号・仮タイトル・橋渡しクラスタ）
- 提案しなかったクラスタペアとその理由（意味的つながりがない場合）
